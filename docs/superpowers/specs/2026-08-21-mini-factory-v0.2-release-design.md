# Mini Factory v0.2 发布准备设计

**日期：** 2026-08-21  
**范围：** 里程碑 D（D1 项目文档、D2 发布验收）

## 目标

将 Mini Factory 的 v0.2 工作树交付为可由新玩家或开发者自行启动、验证和部署的试玩版本。交付重点是准确文档与可重复的发布验收，不改变游戏规则，也不实际发布到任何外部账号。

## 非目标

- 不创建或修改 Cloudflare 账号、Worker 名称、域名、路由、密钥或环境变量。
- 不执行 `wrangler deploy`，不产生外部部署。
- 不添加 CI、云同步、账号、排行榜或新的游戏功能。
- 不修改关卡参数、生产模型或 UI 行为。

## 方案选择

采用“README + 本地验收”的轻量方案。

当前项目已有 Vinext、Cloudflare Vite 插件、`worker/index.ts` 和构建阶段生成的 Wrangler 部署描述，适合在 README 说明 Cloudflare Workers 发布前提与命令。账号专属信息尚未确定，因此不提交伪造的 `wrangler.jsonc` 或部署脚本。

## D1：README 结构

将 `game/README.md` 从 starter 模板替换为中文项目文档，按以下顺序组织：

1. **项目简介**：Mini Factory v0.2 是五关自动化产线试玩版；列出本版本不包含账号、云同步、排行榜等能力。
2. **环境与安装**：Node.js `>=22.13.0`、`npm install`、开发服务器启动命令。
3. **常用命令**：用表格说明 `dev`、`build`、`start`、`test`、`lint`、`install:e2e`、`test:e2e`；标明首次运行 E2E 要下载 Chromium。
4. **玩法说明**：设备放置、输出端口到输入端口的连接、运行时布局锁定、暂停编辑后的重新开始，以及第 1～5 关递进结构。
5. **本地进度**：进度、最佳成绩和非运行布局保存在浏览器 `localStorage`；运行中的生产状态不保存；清除进度会二次确认并恢复第 1 关。
6. **Cloudflare Workers 部署**：说明项目已通过 Cloudflare Vite 插件与 Worker 入口构建；发布者应先登录自己的 Cloudflare 账号，运行构建，再在项目根执行 `npx wrangler deploy`。明确 Worker 名称、域名和账号权限由发布者配置，本文不替用户创建外部资源。
7. **验证与问题定位**：给出最短验收命令顺序，以及 E2E 固定端口或浏览器缺失时的处理方式。

README 的命令与说明必须只引用当前 `package.json` 已有脚本和仓库已存在的部署结构。

## D2：发布验收

### 自动验收

在 `game/` 目录依次执行：

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
npm.cmd run test:e2e
```

验收通过的证据是每条命令的零退出码。E2E 中的完整第 1 关通关用例约需 45 秒，属于正常时长。

### 手动验收清单

提供给用户执行，不由自动化伪造：

1. 依次试玩第 1～5 关，确认进入、生产、结算和解锁链路没有阻断。
2. 在已解锁关卡摆放并连接设备，刷新页面，确认恢复该关草稿且未出现错误弹窗。
3. 使用“清除进度”，分别验证取消不改变数据、确认后回到第 1 关。
4. 将浏览器窗口缩窄到常见桌面窄宽，确认关卡按钮、控制栏、设备卡片和连线时间标签仍可操作和阅读。

手动问题按“阻断流程 / 视觉可用性 / 非阻断文案”分类。阻断流程或关键视觉可用性问题会阻止 v0.2 发布；非阻断文案问题记录为后续优化。

## 可靠性与边界

- README 只描述已经存在的本地存档行为，不承诺跨浏览器、跨设备或云端同步。
- Cloudflare 发布命令仅在用户拥有已认证账号和合适项目配置时执行；发布失败不应通过修改游戏代码来掩盖。
- 自动验收失败时，先保留完整错误输出，再按失败命令定位；不跳过失败项宣布发布完成。

## 验收标准

- README 包含环境要求、启动、构建、测试、玩法、本地存档与 Cloudflare Workers 部署说明。
- 所有命令与当前项目脚本保持一致。
- 自动验收四项均通过。
- 用户获得可执行的手动验收清单，且未授权的外部部署不会被执行。
